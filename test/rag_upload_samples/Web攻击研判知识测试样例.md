# Web 攻击研判知识测试样例

## SQL 注入：登录接口布尔盲注

适用场景：登录、搜索、订单查询等接口将用户输入直接拼接到 SQL 语句。

典型证据：请求参数出现引号闭合、`OR 1=1`、`UNION SELECT`、数据库注释符，或出现 `SLEEP()`、`BENCHMARK()` 等时间延迟函数。单独出现英文单词不应直接判定攻击，应同时结合参数位置、编码还原、语法组合和响应差异。

风险判断：若 Payload 形成完整 SQL 语义并引起认证绕过、数据回显或稳定延迟，可判为高危 SQL 注入；只有单引号且无上下文证据时应进入候选复核，而非直接告警。

处置建议：立即使用参数化查询；限制数据库账号权限；隐藏数据库错误；对命中请求保留原始证据；确认攻击后临时封禁来源 IP，并排查同一来源在相邻时间窗口内的扫描、爆破和注入行为。

## XSS：可执行脚本上下文

典型证据：用户可控内容未经上下文编码进入 HTML、属性、URL 或 JavaScript 执行位置，Payload 包含事件处理器、脚本标签、危险协议或可执行 DOM 片段。应区分被编码为普通文本的输入与真正进入可执行上下文的输入。

处置建议：按输出上下文执行 HTML、属性、URL 或 JavaScript 编码；启用严格 CSP；避免不安全 DOM API；对富文本使用成熟白名单净化器。

## 暴力破解：行为窗口判定

典型证据：同一来源 IP 在短时间内对认证接口发起大量失败请求，用户名或口令呈字典变化，并伴随固定客户端特征。单次登录失败不是暴力破解，应按来源、接口和时间桶聚合后判定。

处置建议：实施渐进式限速、失败锁定、MFA、弱口令检查和异常来源封禁；聚合上报攻击次数、目标账号数、窗口时间和成功与否，避免每个请求生成一条告警。
